# GENIQ CMS — инструкция для владельца сайта

Редактор сайта открыт по адресу:

**https://geniq-system.ru/admin/**

Он сохраняет изменения в репозиторий `nataligalagan88264-dotcom/geniq_website`, ветку `main`. После публикации Vercel автоматически собирает новую версию сайта.

## Как войти

1. Откройте `https://geniq-system.ru/admin/`.
2. Нажмите **«Войти через GitHub»**.
3. Войдите в GitHub-аккаунт, которому выдан доступ на запись в репозиторий сайта.
4. Если GitHub впервые просит разрешить приложение GENIQ CMS, подтвердите доступ.

Пароль от GitHub, токены и секреты CMS никому передавать не нужно.

## Что можно менять без разработчика

- **Общие настройки:** меню, ссылка на анкету, Telegram, Instagram, фото автора, контакты и юридические данные.
- **Главная страница:** первый экран, подписи, кнопка, видео головы, карточки продуктов.
- **Отзывы:** имя, профессия, Telegram, нейротип, запрос, цитата, основной текст, аватар, видео и обложка видео.
- **Вопросы и ответы:** вопросы и тексты раскрывающихся ответов на главной странице.
- **Блог:** заголовки, категории, карточки будущих статей и ссылки.
- **SEO:** title, description, изображение для соцсетей и данные sitemap основных страниц.

Сложную компоновку, анимации, программную логику, новые типы блоков и тексты структурных страниц «О системе», «Нейротипы», «Подход» и «Партнёрам» безопаснее менять через разработчика.

## Как опубликовать изменение

1. Выберите раздел слева.
2. Измените только нужные поля.
3. Проверьте орфографию, ссылки и предпросмотр изображения.
4. Нажмите **Publish / Опубликовать** и подтвердите публикацию.
5. Подождите обычно 1–3 минуты: GitHub сохранит изменение, а Vercel пересоберёт сайт.
6. Откройте сайт в новой вкладке и обновите страницу. Если браузер показывает старую версию, используйте приватное окно или очистите кэш страницы.

Не нажимайте Publish несколько раз подряд. Дождитесь завершения первой сборки.

## Изображения и видео

- Для фотографий используйте JPG или WebP; для графики с прозрачностью — PNG или WebP.
- Желательный размер фотографии: до 2000 px по длинной стороне и до 1–2 МБ.
- Для видео используйте MP4 (H.264), желательно до 20–30 МБ.
- Для каждого видео загрузите отдельную обложку, чтобы карточка выглядела аккуратно до запуска.
- Не удаляйте медиафайл, пока он используется хотя бы в одном поле.
- Поле **«Позиция аватара»** обычно менять не нужно. Формат `50% 32%` означает горизонтальный и вертикальный центр кадрирования.

## Правила для текста и SEO

- Не вставляйте текст целиком заглавными буквами.
- Не добавляйте в заголовок HTML, Markdown или эмодзи, если это не предусмотрено дизайном.
- Title рекомендуется держать примерно в пределах 45–65 символов, description — 120–170 символов.
- Основной адрес сайта — `https://geniq-system.ru`. Домен `.com` только перенаправляет на него.
- Не создавайте отдельную FAQ-страницу: вопросы находятся блоком на главной.
- После изменения SEO не меняйте canonical, robots.txt или sitemap вручную: они формируются сборкой сайта.

## Как отменить неудачную публикацию

Самый безопасный способ — сразу сообщить разработчику, что именно было изменено. Версию можно вернуть через историю GitHub или откатить deployment в Vercel.

Если ошибка только в одном поле, исправьте его в CMS и опубликуйте ещё раз. Не удаляйте репозиторий, проект Vercel, домены или DNS-записи.

## Если редактор не открывается

1. Проверьте, что открываете именно `https://geniq-system.ru/admin/`.
2. Попробуйте приватное окно браузера.
3. Убедитесь, что GitHub-аккаунт имеет доступ к репозиторию.
4. Если появляется `GITHUB_CLIENT_ID is not configured`, в Vercel отсутствуют переменные OAuth — это должен исправить разработчик.
5. Если публикация прошла, но сайт не обновился за 10 минут, проверьте последний deployment в Vercel и передайте разработчику текст ошибки.

## Техническая настройка OAuth

Этот раздел нужен только разработчику или администратору Vercel.

GitHub OAuth App:

- Application name: `GENIQ CMS`
- Homepage URL: `https://geniq-system.ru`
- Authorization callback URL: `https://geniq-system.ru/api/callback`

Переменные Vercel для Production:

- `GITHUB_CLIENT_ID`
- `GITHUB_CLIENT_SECRET` (Sensitive)

После изменения переменных требуется новый Production Deployment. Секрет нельзя добавлять в Git или в публичные документы.

## Локальная проверка редактора

Из папки `frontend` в первом терминале:

```bash
npx decap-server
```

Во втором терминале:

```bash
npm start
```

Затем откройте `http://localhost:3000/admin/`. Локальный режим использует `local_backend: true` и не требует GitHub OAuth.

## Чек-лист перед закрытием проекта

- основной домен и HTTPS работают;
- `.com` перенаправляет на `.ru`;
- CMS открывается и пользователь может войти;
- тестовая правка из CMS успешно попадает в GitHub и Vercel;
- у клиента есть доступы к GitHub, Vercel, REG.RU, Google Search Console и Яндекс Вебмастеру;
- OAuth Client Secret и остальные секреты хранятся только в Vercel;
- назначен человек, который будет делать резервные копии и проверять обновления сайта.
